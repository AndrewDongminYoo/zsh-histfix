# histfix standalone plugin

## Problem

History-based zsh suggestions repeat mistyped commands.
Editing a history file by hand is cumbersome, and merging selected entries into one edited command loses record boundaries.

## Approved scope

Publish `histfix` as a standalone public repository with a reviewable feature PR and CI.
Retain a separate Homebrew tap PR for packaging and discovery.
Reuse the plugin and tests developed in the tap without expanding the product scope.

- `histfix replace FIND REPLACEMENT` performs literal substitution in each command.
- `--regex` enables Python regex syntax and numbered dollar capture references.
- Preview shows individual before/after entries and requires confirmation.
- `--dry-run` previews without replacements; `--ignore-case` controls case sensitivity.
- Direct `histfix` calls are excluded from replacement.
- Replacement preserves record boundaries, timestamps, and untouched bytes.
- The invoking zsh refreshes its existing events after a successful write, preserving order and duplicate counts.
- Apply and undo refuse before replacement if memory-only events, ambiguous occurrences, or an incomplete snapshot prevent a safe refresh.
- ~~With `SHARE_HISTORY` enabled, apply and undo refuse before flushing; dry-run remains available.~~ Superseded on 2026-10-10; see the reconciliation below.
- `undo` restores the previous replacement and keeps subsequently appended records.
- Conflicting changes during preview or before undo cause a refusal.

## Non-goals

Automatic typo inference, command execution, key bindings, record deletion, full VS Code regex compatibility, and automatic synchronization of other shells are outside this baseline.
Merge, release tagging, and unrelated repository changes require separate authority.

## Acceptance

1. Run `make check` against temporary histories, including a real interactive zsh pseudoterminal.
2. Run CI on Linux with Python 3.9 and 3.14, and on macOS with Python 3.14.
3. Verify that tests do not read the operator's history or startup files.
4. Validate the Homebrew formula against the standalone source layout.
5. Open a plugin PR and a dependent tap PR under the personal GitHub account.

## Constraints

Use Python's standard library without runtime package installation.
Close other shells sharing the history file before applying changes; their in-memory state cannot be refreshed by this plugin.
History flushing can append pending commands even if replacement is cancelled or preview-only.
No visual approval is needed because this change introduces no visual design or rendered asset.

## Reconciliation 2026-10-10: SHARE_HISTORY support

The operator decided in [issue #7](https://github.com/AndrewDongminYoo/zsh-histfix/issues/7) to support replacement and undo with `SHARE_HISTORY` enabled.
Oh My Zsh enables that option by default, so the refusal blocked replacement for its default configuration.
The shipped `histfix.plugin.zsh` is the authority for this behavior, and `test_share_history_applies_and_undoes_without_duplicates` and `test_share_history_preview_keeps_disk_and_memory` cover it.

The refusal was based on the observation that `fc -R` cannot reset zsh's shared-history read position.
That observation still holds.
After a successful replacement or undo with `SHARE_HISTORY`, the plugin now runs `fc -p "$HISTFILE"` with the caller's `HISTSIZE` and `SAVEHIST`, which reads the rewritten file into a new history level and resets that position.
The reload is borrowed from `marlonrichert/zsh-hist`; its `fc -W` rewrite from memory is not, because the file-based rewrite keeps records that exist only on disk.

The memory-only refusal in the scope above still applies without `SHARE_HISTORY`.
With `SHARE_HISTORY`, other shells' imports change the event list at every prompt, so no snapshot is taken.
Memory-only events disappear from the current shell's list, and the previous history level keeps the old commands until the shell exits.
The README section "Removing sensitive text" lists where old text can remain.
